# Inference Manager

The `InferenceManager` loads an exported LEAPP graph and runs the full pipeline at inference time — no tracing or annotation required.

## Usage

```python
from leapp import InferenceManager

# Load from the generated YAML description
manager = InferenceManager("path/to/my_graph/my_graph.yaml")

# Inspect expected inputs/outputs
print(manager.inputs)   # e.g. ['preprocessing/joint_pos', 'preprocessing/joint_vel']
print(manager.outputs)  # e.g. ['inference/predictions']

# Generate mock inputs for testing (correct shapes, dtypes, devices)
mock_inputs = manager.get_mock_input()

# Run the full pipeline
outputs = manager.run_policy(mock_inputs)
# or equivalently:
outputs = manager(mock_inputs)
```

## Key Details

- **Input/output keys** use the format `node_name/tensor_name` (e.g. `'preprocessing/joint_pos'`).
- **`get_mock_input()`** generates random tensors matching each input's shape, dtype, and device — useful for smoke-testing exported graphs.
- **`run_policy(inputs)`** executes nodes in pipeline order, routing outputs between nodes as defined in the YAML graph. Returns a dict of the final pipeline outputs.
- On construction the manager **validates** all pipeline connections (shape/dtype compatibility) and loads the exported models (JIT or ONNX) specified in the YAML.

## Initializing Feedback State

Graphs with feedback connections (see [Advanced Graph Operations](3_advanced_graph.md)) carry state between calls to `run_policy()`. Internally, all node inputs — including feedback inputs — are initialized to **zero tensors**. If the original model had non-zero initial state, you must set those values before the first `run_policy()` call using `set_input_value()`:

```python
manager = InferenceManager("my_graph/my_graph.yaml")

# Initialize feedback inputs to match the original model's initial state
manager.set_input_value("odometry_processor", "prev_transform",
    torch.tensor([0.05, 0.02, 0.01, 0.99, 0.0, 0.01, 0.0, 999.0, 0.0],
                 dtype=torch.float32, device='cuda'))
manager.set_input_value("odometry_processor", "ego_speed",
    torch.zeros(1, dtype=torch.float32, device='cuda'))

# Now run — feedback values will carry forward across iterations
for sensor_reading in sensor_stream:
    outputs = manager.run_policy(sensor_reading)
```

You can discover which inputs are feedback-driven by inspecting `manager.feedback_inputs` or checking the `feedback_flow` section of the generated YAML.

## Input / Output Key Format

All keys passed to `run_policy()` and returned in its output dict follow the format `node_name/tensor_name`.

**Discovering valid keys:**

| Property | Returns | Example |
|---|---|---|
| `manager.inputs` | List of expected input keys | `['process_odom/lin_vel_I', 'process_odom/q_IB']` |
| `manager.outputs` | List of output keys | `['post_process_actions/actions']` |
| `manager.feedback_inputs` | Feedback input targets | targets from `feedback_flow` |

A `ValueError` is raised if a key passed to `run_policy()` does not match the `node_name/input_name` format.

## API Reference

### Constructor

```python
InferenceManager(model_path: str, verbose: bool = False)
```
- `model_path` — path to the `.yaml` graph description generated by `compile_graph()`.
- Loads all models, validates pipeline connections (shape/dtype), and pre-allocates value buffers.

### Methods

| Method | Description |
|---|---|
| `run_policy(inputs, verbose=False)` | Run the full pipeline. `inputs` is a dict of `'node/tensor'` → `torch.Tensor`. Returns a dict of final output tensors. |
| `get_mock_input()` | Generate random tensors for every external pipeline input with correct shape, dtype, and device. |
| `set_input_value(node_name, input_name, value)` | Directly set a node's input buffer (useful for initializing feedback state). |

### Properties

| Property | Type | Description |
|---|---|---|
| `inputs` | `list[str]` | Expected input keys (`node_name/input_name`). |
| `outputs` | `list[str]` | Output keys (`node_name/output_name`). |
| `feedback_inputs` | `list` | Feedback input targets from the YAML `feedback_flow`. |
